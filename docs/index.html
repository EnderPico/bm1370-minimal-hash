Introduction

This project is a theoretical and practical exploration of the Bitmain BM1370, a Bitcoin mining ASIC. The goal is to bring up the chip with a minimal hardware and firmware setup and demonstrate valid hash computation at low power.

The focus is on understanding, documentation, and hardware/software co-design — not on profit-oriented mining or multi-chip scaling.

Project Scope

  • Goal: Minimal bring-up of a single BM1370 chip with valid SHA-256 hash output.
  • Controller: Raspberry Pi Pico 2 — chosen for deterministic timing, strong debugging support, and flexibility via PIO for custom protocols.
  • Non-goals: Full 1.2 TH/s performance, profit-oriented mining, multi-chip scaling.

Current status: Phase 0 — Research

Technical Specifications

The following specifications were gathered during Phase 0 research, primarily from community sources and the open-source ESP-Miner project by Bitaxe.

Power Architecture

Input Power
Supplied via a 5 V rail, capable of delivering >4 A (accounting for conversion losses at >20 W total consumption).
Core Supply (VDD)
Nominal ~1.2 V, high-current rail. Peak current reaches 15–20 A depending on operating conditions. Reference designs use a high-current buck converter such as the TPS546D24.
IO Supply — VDDIO_12
Nominal ~1.2 V, low-current rail supplying IO logic and internal support circuitry.
IO Supply — VDDIO_08
Nominal ~0.8 V, low-current rail. Exact current requirements are not publicly documented.
Ground (VSS)
Must be connected with low-impedance paths to support high transient currents on the core rail.

Communication Interface

Protocol
Proprietary, UART-like bidirectional communication over 6 signals.
Controller → ASIC (4 signals)
CI, BI, NRST, PIN_MODE
ASIC → Controller (2 signals)
CO, BO

Clocking

External Clock
25 MHz oscillator connected to CLKI (input) and CLKO (output).

Firmware Implementation

The BM1370 communicates via framed serial packets. Two packet types exist: command packets (using CRC-5 error detection) and job packets (using CRC-16). The packet structure follows the pattern:

bm1370_protocol.h 
#ifndef BM1370_PROTOCOL_H
#define BM1370_PROTOCOL_H

#include <stdint.h>
#include <stddef.h>

/*
 * BM1370 packet types
 */
typedef enum {
    BM1370_PACKET_CMD,
    BM1370_PACKET_JOB
} bm1370_packet_type_t;

/*
 * Packet structure:
 * [ PREAMBLE ][ HEADER ][ LENGTH ][ DATA... ][ CRC ]
 *
 * CMD packets use CRC5
 * JOB packets use CRC16
 */

int bm1370_build_packet(
    uint8_t *buffer,
    size_t buffer_size,
    bm1370_packet_type_t type,
    const uint8_t *data,
    size_t data_len
);

#endif

The implementation constructs the packet frame byte-by-byte: a 0x55 0xAA preamble, a type-dependent header, the payload length, the raw data, and finally the appropriate CRC checksum.

bm1370_protocol.c 
#include "bm1370_protocol.h"
#include <string.h>
#include <stdbool.h>
#include "crc16.h"
#include "crc5.h"

int bm1370_build_packet(
    uint8_t *buffer,
    size_t buffer_size,
    bm1370_packet_type_t type,
    const uint8_t *data,
    size_t data_len
) {
    size_t offset = 0;
    size_t total_length;

    if (!buffer || !data) {
        return -1;
    }

    if (type == BM1370_PACKET_JOB) {
        total_length = data_len + 6;
    } else if (type == BM1370_PACKET_CMD) {
        total_length = data_len + 5;
    } else {
        return -1;
    }

    if (buffer_size < total_length) {
        return -1;
    }

    /* Protocol preamble (synchronization bytes) */
    buffer[offset++] = 0x55;
    buffer[offset++] = 0xAA;

    /* Header: 0x20 = job, 0x40 = command */
    buffer[offset++] = (type == BM1370_PACKET_JOB) ? 0x20 : 0x40;

    /* Payload length field */
    buffer[offset++] = (type == BM1370_PACKET_JOB)
        ? (uint8_t)(data_len + 4)
        : (uint8_t)(data_len + 3);

    /* Copy payload */
    memcpy(&buffer[offset], data, data_len);
    offset += data_len;

    /* Append error-detection checksum */
    if (type == BM1370_PACKET_JOB) {
        uint16_t crc16_total = crc16_false(&buffer[2], data_len + 2);
        buffer[offset++] = (crc16_total >> 8) & 0xFF;
        buffer[offset++] = crc16_total & 0xFF;
    } else {
        buffer[offset++] = crc5_compute(buffer + 2, data_len + 2);
    }

    return (int)offset;
}

Research Journal

A chronological record of research progress, findings, and open questions encountered during Phase 0.

  1. Week 01 — Hardware Research Focused on understanding BM1370 basics and minimum requirements. Mapped out power domains (VDD core at ~1.2 V / 15–20 A, IO rails at 1.2 V and 0.8 V), identified the 6-signal UART-like communication interface, and confirmed the 25 MHz external clock requirement. Identified Bitaxe as the only known minimal reference design.
  2. Week 02 — Protocol Analysis Studied the open-source ESP-Miner codebase to understand the BM1370 control flow. Mapped the initialization sequence, job creation pipeline, and ASIC response handling. Documented the packet framing protocol (preamble, header, length, data, CRC) and implemented a standalone bm1370_build_packet() function with CRC-5 and CRC-16 support.
